# 生命周期与扩展模型

## 总体原则

一期是单用户、用户主动触发的本地工具。长任务仅限外部行情请求和信息搜索，不引入后台队列、定时任务或分布式事件。所有修改操作在本地形成明确提交点；失败时保持最后一个有效状态。

## 研究对象生命周期

```text
不存在
  -> 候选已选择
  -> 创建并可用
  -> 活跃研究
  -> 删除
```

- 创建发起者：用户选择证券候选。
- 创建守卫：证券身份合法且本地不存在；若已存在则直接进入“活跃研究”。
- 活跃状态：时间范围、K 线周期、筛选条件和图表位置可以反复更新。
- 删除发起者：用户明确确认删除。
- 删除动作：先解除全部事件关联，再删除对象与页面状态；事件实体和行情缓存不随对象删除。
- 删除失败：事务回滚，对象保持可用。
- 一期不提供归档和恢复已删除对象；以后再次选择同一证券会创建新研究对象，并可重新关联保留的事件。

## 行情请求生命周期

```text
Idle
  -> Planning（读取缓存并计算缺口）
  -> FetchingPrimary
      -> Validating -> Persisting -> Completed
      -> FetchingFallback -> Validating -> Persisting -> CompletedWithWarning
  -> Failed
  -> Retry -> Planning
```

### 规则

- 用户打开研究页、改变区间或主动刷新可触发请求；周期切换只聚合本地日线，不触发外部请求，除非底层区间缺失。
- 同一研究对象的重叠行情请求采用“最新请求生效”：旧请求可以完成缓存写入，但不得覆盖新请求的页面结果。
- 主源失败后立即尝试备用源；不在单次用户操作内无限重试。
- 请求超时视为该源失败；主源超时后进入备用源，备用源超时后失败。
- 用户离开页面可取消页面等待；已成功取得且通过校验的数据允许完成缓存提交。
- 保存采用原子提交；验证或保存失败时保留旧缓存。
- 部分区间成功进入 `CompletedWithWarning`，图表显示实际覆盖范围。

## 信息搜索会话生命周期

```text
NotStarted
  -> Searching(page=1)
  -> ResultsAvailable
      -> LoadingNextPage -> ResultsAvailable
      -> CandidateSelected -> DraftEditing
      -> Cancelled/Expired
  -> Failed -> Retry
```

- 只有用户点击搜索才创建会话。
- 搜索条件改变时，旧会话失效并创建新会话；旧结果不得混入新条件。
- 离开研究页面、刷新应用或关闭服务后，未确认候选过期并丢弃。
- 同一页重复请求按候选指纹去重，但不写入事件库。
- 取消或失败不影响已有事件。

## 事件草稿与事件生命周期

### 草稿

```text
Created（来自候选或手工）
  -> Editing
  -> Validating
      -> DuplicateWarning -> Editing or Confirming
      -> Invalid -> Editing
      -> Confirming -> Saved
  -> Cancelled
```

- 草稿不持久化；应用异常退出时允许丢失未保存编辑。
- 必填项合法后才能确认。
- 重复提示不改变草稿，也不强制阻止保存。
- 保存进行中禁止重复提交；保存失败返回 Editing 并保留当前表单内容。

### 已确认事件

```text
Active
  -> Editing -> Active
  -> LinksChanging -> Active
  -> DeletePending -> Deleted
```

- 内容和全部对象关联在一次提交中更新。
- 删除必须用户确认；失败则回到 Active。
- 事件至少有一个关联对象才能首次保存。删除对象导致最后关联解除后，事件允许成为“未关联事件”并继续保留，以满足删除研究对象不删事件的规则。
- 未关联事件一期不在首页单独展示，但可在新增/编辑关联时被检索复用；具体入口由 Phase 4 页面设计确认。

## 图表投影生命周期

投影是无持久状态的派生结果：

```text
BarSeries / Events / Filters / Period changed
  -> Validate inputs
  -> Map dates
  -> Aggregate same-bar events
  -> Render projection
```

- 任一输入变化都重新计算。
- 计算失败不改变事件或行情，仅清除无效投影并显示问题。
- 点击聚合标记改变当前选中事件，不修改领域数据。

## 应用启动与停止

```text
Stopped -> Starting -> Ready -> Stopping -> Stopped
                  \-> StartFailed
```

- 桌面快捷方式发起启动，服务加载本地数据并通过自检后才打开浏览器。
- 端口占用或本地数据不可读时启动失败，显示可操作错误，不创建第二份数据目录。
- 关闭启动窗口发起停止；已提交数据保留，未确认搜索结果和草稿允许丢失。

## 扩展点与模式决定

| 变化点 | 决定 | 合同与时机 | 失败策略 | 拒绝的复杂方案 |
| --- | --- | --- | --- | --- |
| 多个证券检索源 | 采用端口+策略 | 请求证券候选时选择可用策略 | 当前源失败可尝试下一源 | 不做动态插件市场 |
| 主/备行情源 | 采用有序回退策略 | 每个缺失区间先主后备 | 结构化 WARNING/EXCEPTION | 不做并行竞速和多数表决 |
| 信息搜索来源 | 采用可替换搜索端口 | 用户显式搜索时调用 | 单源/聚合失败不污染事件 | 一期不做通用爬虫插件框架 |
| 日/周/月聚合 | 采用周期策略 | 图表周期变化时运行纯函数 | 输入非法则拒绝 | 不用 State Pattern |
| 候选规范化与验证 | 采用明确流水线 | 搜索响应后按固定顺序执行 | 单项警告或整页失败 | 不用隐式拦截器 |
| 事件保存后刷新 | 采用进程内领域事实通知 | 本地提交成功后通知独立只读视图刷新 | 监听失败可重新加载，不回滚事件 | 不用消息队列 |
| 结构化问题转 UI | 采用应用边界统一转换 | 每次用例返回时 | 不暴露堆栈，保留日志原因 | 不在领域层拼提示文案 |

## 扩展合同细节

### 行情提供端口

- 输入只包含证券身份和日期区间。
- 输出标准化前的来源批次及来源标识。
- 适配器不能直接写缓存，也不能决定是否覆盖冲突。
- 执行顺序由行情职责固定：主源后备用源。

### 信息搜索端口

- 输入为搜索词、起止日期和页码，不接收事件仓储。
- 输出候选页和是否还有下一页。
- 适配器失败只能影响当前搜索请求。

### 进程内领域事实

- 仅通知“事件已确认/修改/删除”这一完成事实。
- 消费者只负责刷新视图和失效只读缓存，不执行二次业务写入。
- 一期允许最多一次同步通知；页面可通过重新读取恢复，因此不需要重试队列。

## 明确拒绝的模式

- 插件框架：一期没有用户独立安装数据源的需求，普通端口适配足够。
- 状态模式：生命周期状态用于说明流程，实际行为简单，不值得为每个状态创建对象。
- 命令队列/后台任务：用户主动、低并发请求，无排队收益。
- 中间件/拦截器承载业务规则：日期映射、重复提示和缓存合并必须留在明确职责中。
- 分布式消息与最终一致性：所有持久化在单机内完成，应优先使用本地事务。

## 安全网审查

- 所有可失败外部操作都有超时、回退或重试入口。
- 搜索取消、页面离开和服务关闭不会写入未确认候选。
- 行情部分成功和事件保存失败都有明确的最后有效状态。
- 删除对象与删除事件不会相互误触发。
- 被接受的扩展点只对应数据源和周期聚合的真实变化；没有预建二期分析插件。
