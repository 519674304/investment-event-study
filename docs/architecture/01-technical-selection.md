# 技术选型

## 量化约束

| 项目 | 一期约束 |
| --- | --- |
| 用户与并发 | 单用户；一个浏览器会话为主，少量并行读请求 |
| 行情规模 | 每对象至少 10 年日线，约 2,500—3,000 条；几十至数百对象仍为小数据量 |
| 事件规模 | 每对象至少 5,000 条；事件可多对象关联 |
| 写入频率 | 用户操作触发，通常每秒远低于 1 次；行情批量写入为短事务 |
| 响应目标 | 缓存命中后 10 年日线首屏 3 秒内；图表交互本地完成 |
| 部署 | Windows 本机，双击快捷方式启动并打开浏览器 |
| 网络 | 行情和信息搜索需要联网；已缓存研究可读取 |
| 运维 | 无专职运维，不运行数据库服务器或后台队列 |
| 安全 | 仅监听本机；无账号、密钥和付费数据 |

## ADR-001：应用形态

**决定：** 本地 HTTP 服务 + 浏览器单页应用。

**选择理由：** 满足用户已确认的本地 Web 形态；图表交互、表单和搜索分页适合浏览器；后端能够绕开浏览器跨域限制并统一访问免费数据源。

**替代方案：**

- Electron/Tauri 桌面壳：可形成原生安装包，但一期增加打包、升级和双运行时成本，拒绝。
- 单文件 HTML：无法可靠承担本地持久化、主备行情源和信息搜索代理，拒绝。

## ADR-002：后端运行时

**决定：** Python 3.12 + FastAPI + Uvicorn，应用用例采用同步领域/仓储代码，外部 HTTP 使用有超时的客户端封装。

**选择理由：** Python 适合行情解析、日期聚合和未来研究分析；FastAPI 提供明确的请求模型和本地 API；单用户负载无需复杂异步数据层。

**替代方案：**

- Node.js 全栈：可以减少语言数量，但未来公司分析和数据处理更适合 Python；拒绝。
- Flask：依赖少，但接口模型、校验和自动契约不如 FastAPI；拒绝。

## ADR-003：前端

**决定：** React + TypeScript + Vite，状态分为服务器数据查询状态和页面交互状态；不引入大型全局状态框架。

**选择理由：** 研究对象列表、搜索分页、保存前编辑、图表和下方事件区存在多个联动组件，React 的组件和 TypeScript 契约能控制复杂度；Vite 支持本地开发和静态构建。

**替代方案：**

- Vue：同样可行，但不带来决定性优势；选择 React 作为统一实现基线。
- 服务端模板 + 原生 JavaScript：初期更少依赖，但图表双向联动、编辑状态和分页容易变成页面脚本堆积；拒绝。

## ADR-004：K 线图表

**决定：** Apache ECharts，采用 Canvas 渲染；K 线、成交量、dataZoom 和事件散点/标记在同一实例中组合。

**选择理由：** 原生支持 candlestick、缩放和点击事件，足以处理数千日线与数千事件；中文生态成熟。事件详情仍由 React 在图表下方呈现，避免把完整内容塞入 tooltip。

**替代方案：**

- Plotly：快速分析图方便，但对高度定制的 K 线事件交互和前端状态联动较重；拒绝。
- TradingView Lightweight Charts：K 线体验好，但事件聚合、成交量与自定义分类交互需要更多适配；暂不选。

## ADR-005：本地持久化

**决定：** SQLite 单文件数据库 + SQLAlchemy 2.0 + Alembic 迁移；启用外键、busy timeout 和 WAL。所有事件及关联修改使用事务。

**选择理由：** 单用户、低写入、关系明确，SQLite 无需服务且事务足够；事件多对象关联、分类标签和行情唯一键适合关系模型。SQLite 在 WAL 模式支持并发读取和单写者，符合负载。

**替代方案：**

- JSON 文件：事件关联、去重、迁移和原子修改脆弱；拒绝。
- PostgreSQL：能力过剩并增加安装运维；拒绝。
- IndexedDB：把数据锁在浏览器配置中，不利于后端行情缓存和未来二期分析；拒绝。

## ADR-006：数据源策略

**决定：** 通过内部端口支持按证券类型路由的数据源适配器：

- A 股股票与常见市场/行业指数：东方财富公开接口作为首选候选，腾讯或新浪公开行情作为备用候选；实施前以契约测试确认字段和历史覆盖。
- 同花顺概念指数：同花顺公开行情端点作为首选候选；若备用源无法提供同一指数，明确显示“该对象无可用备用源”，不拿近似指数替代。
- 证券搜索：东方财富证券搜索候选 + 同花顺概念索引候选，统一规范为 `SecurityCandidate`。
- 信息搜索：首个适配器使用无需密钥的公开网页搜索/RSS 结果，只保存标题、日期、来源、摘要、链接；具体入口以实施时可用性契约测试为准。

这里“主备”是能力路由，不承诺每一种概念指数都有两个等价免费来源。严禁用代码相似或名称相近的指数静默替换。

**替代方案：**

- 依赖单一综合数据包：其底层免费接口仍可能变化，且对同花顺概念覆盖不确定；拒绝作为领域依赖。
- 预先下载全市场：与按需查询要求冲突；拒绝。

## ADR-007：Windows 分发与启动

**决定：** 发布为版本化应用目录，包含后端可执行运行环境和已构建前端；桌面快捷方式调用启动器。启动器选择空闲本机端口、启动服务、健康检查成功后打开默认浏览器；控制台窗口关闭时终止服务。

开发阶段使用 Python/Node 工具链；发布版不要求用户手工运行 `pip install` 或 `npm install`。

**替代方案：**

- 要求用户每次在源码目录运行命令：不符合双击启动验收；拒绝。
- 注册 Windows 服务：一期不需要后台常驻；拒绝。

## ADR-008：不引入中间件

一期明确不使用 Redis、消息队列、独立搜索引擎、对象存储、工作流引擎、容器编排和插件框架。量化负载可由单进程和 SQLite 满足，引入这些组件只会增加部署与恢复成本。

## 技术选择可逆性

- 行情和信息源位于适配器后，可替换而不改变领域规则。
- ECharts 只消费图表视图模型；替换图表库不改变事件映射。
- SQLite 由仓储端口隔离；二期若出现多用户需求，可迁移数据库而不修改领域实体。
- 前后端通过版本化 API DTO 通信，数据库记录不直接暴露给 UI。
